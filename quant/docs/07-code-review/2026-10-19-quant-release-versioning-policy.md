# quant 扩展层发布版本策略（v1 起）

> 建立日期：2026-10-19；首个版本：`quant-v1.0.0`（tag 指向 `9351e5ab`，Modal 部署 v20）。
> 适用范围：本仓库自定义扩展层（`quant/` 与自定义 `.github/workflows/`）；与上游 Qlib 的 `v0.*` tags 相互独立。

## 版本号

`quant-vMAJOR.MINOR.PATCH`

| 级别 | 触发条件 | 示例 |
| --- | --- | --- |
| **MAJOR** | 不兼容的契约/数据结构变更（账本格式、工件 schema、发布/执行契约的破坏性变更） | journal/fixture 状态格式重构且无法兼容旧锚点 |
| **MINOR** | **策略参数或执行契约变更**（候选模型、持仓规则、标签期限、T-close → T+1-open 时序、成本口径、三池组成等） | 换用新冻结候选、Top10/Drop1 规则调整 |
| **PATCH** | **纯缺陷修复与工程改进**，不改变策略参数与执行契约 | R01–R10 修复、记账原子性、CI/文档、安全加固 |

约定（与操作员确认）：策略参数/执行契约变更走 **minor**；纯修复走 **patch**。

## Tag 规则

- 命名 `quant-vX.Y.Z`；打在**已合并 main 且完成独立复审**的提交上，且该提交应与当前 Modal 部署的提交标记一致（部署版本写入注释）。
- 注释必须包含：目标提交 SHA、部署版本、变更范围、证据文档路径。

## Release 规则

- 每个 tag 创建对应 GitHub Release，说明中至少包含：
  1. 变更范围与关键保障（对照审查编号）；
  2. 最近一次生产验证事实（发布日期、工件提交、journal/账本链状态）；
  3. 证据文档链接；
  4. 是否包含策略参数变化（MINOR/MAJOR 必须给出冻结对象变化与独立验收记录；PATCH 不改变任何冻结对象）。
- 发布与部署分离授权：tag/release 不等于部署；部署需单独授权（沿用 2026-10-18 记录中的操作员流程）。
