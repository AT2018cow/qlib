## 1. 目标与已知边界

目标是在用户计划下周使用前，回答三个具体问题：当前三套策略经纠错后是否仍可作为使用候选；主要竞争者是否有足够稳定的优势支持替换；程序是否能按实际账户和交易方式可靠生成、核对和执行订单。

不以积累 120 个新前向交易日作为本次复验的启动或完成条件，也不把短期复验宣称为长期盈利或“全局最佳”证明。原研究晋级的 120 日要求保持独立；如实施有限上线流程，应新增明确状态和合同，不能删除该要求、伪造前向日期或把参考回测标为研究晋级通过。

已知依据见[修复验收记录](2026-11-06-extension-repair-acceptance.md)：12 个基础执行单元纠错后 CAGR 最大变化 14.1561 个百分点，但它们是 100M 历史参考账户，不能代替当前 1M 配置的复验；380 份报告指标复算也不等于 380 次重新成交回放。历史 ST、官方除权参考价、开盘流动性及云端验证仍有证据缺口。

### P1：现任复验的具体检查

- 尽可能覆盖原选择区间，并单列已消费的确认区间和最近完整交易日窗口。实施时根据真实覆盖冻结日期，保留缺口，不用较短或有利区间冒充完整验证。
- 统一 T-close 评分、T+1-open 执行、20 交易日重训及各市场既有标签和 TopK/DropN；费用从已冻结合同读取，不能为提高结果临时降低。
- 核对 ST、停牌、涨跌停、上市日期例外、复权坐标、持仓退指后报价、订单数量、费用及现金守恒。缺历史状态的结果标为参考，不能输出“完全可成交”。
- 收益、最大回撤、Sharpe 等均由核对后的同一净值路径计算；输出换手、费用、无法成交及部分成交、现金比例、最大单股权重和可获得的行业集中度。
- 对近期模拟账户核对信号、计划订单、成交假设与结算；如存在实盘成交记录，另行核对券商实际成交，绝不能把开盘价模拟成交当作券商成交。

### P2：有限重排规则

每市场最多 4 个候选（含现任），全轮最多 12 个。优先顺序为现任、最近一轮已记录的主要竞争者、旧生产对照，剩余名额才用于一个有现成证据的邻近持仓配置。候选具体 ID、区间、排序规则和成本情景在查看新结果前登记；若有效候选不足，不为凑数量新造模型。

基础比较使用一致的可比区间；候选独有的更长历史单独披露。先排除执行与数据不合格项，再比较扣费后风险收益、分期表现、回撤和恢复时间、换手及相位稳定性。能够取得冻结相位预测时复用，不能取得时明确稳定性未验证。

预设额外单边 0 / 5 / 10bp 作为敏感性情景，不把它们称作已校准的真实冲击成本。容量结论必须有对应日期的开盘流动性证据；缺失时只给费用敏感性结果。算术 overlay 只能作诊断，若推荐实际使用，需另有逐笔执行回放。

替换建议至少需要：同口径净 Sharpe 和回撤不同时恶化，优势不只来自一个短窗口，成本压力下方向不反转，现有分期/相位证据不显示明显不稳；这些只形成建议，不构成统计显著性或自动晋级。证据相近或不足时，不声称发现新赢家；现任也只有在自身合格时才可保留。任何更具体的收益/回撤容忍阈值需在新结果产生前冻结，不根据赢家倒推标准。

### P3：生产与使用方式验收

优先在隔离输出位置模拟运行，不直接重放到正式账户或发布目录。检查行情新鲜度、模型与标签截止日、实际交易日、账户身份、现金持仓衔接、历史价格修订、重试幂等、任务中断恢复及前端一致性。凭证和账户私密资料不写入报告。

冻结代码并完成回归后才形成部署包。包含旧版本与状态备份、变更范围、迁移检查、失败回滚步骤和验收记录。回滚不能覆盖新发生的真实成交，也不能退回已知不安全代码后恢复下单；必要时停用执行、保留账本并人工核对。

如需要 Modal 验证，先登记有界批次、预算和可信最坏耗时。使用持续附着的前台会话直到真实退出；不得使用 Modal `--detach`、`nohup` 或后台任务代替。工具无法覆盖耗时时暂停该云任务，提出有界替代方案。真实输出、退出码、版本、app ID 和费用证据归档，启动成功不算验收成功。

## 4. 有限上线状态与停止条件

拟议状态与现有研究晋级状态并列，不复用 `promotion_eligible=True` 表示有限上线：

| 状态 | 含义与允许动作 |
|---|---|
| `BLOCKED` | 账本、数据、执行或运行证据不合格；不生成可下单的有效决策 |
| `REFERENCE_ONLY` | 历史证据存在缺口；仅供查看和诊断，不能据此认证可交易性 |
| `READY_FOR_LIMITED_REVIEW` | 技术复验完成，拟用市场、预算、限制和剩余不确定性列明；等待具体上线包审核 |
| `LIMITED_APPROVED` | 用户批准具体版本和范围后的有限使用状态；持续核对，仍不宣称长期验证完成 |

有限使用前明确资金、账户隔离、市场和执行方式；可选的风险上限由用户决定，不自行填入默认值。用户已确认三市场独立 1M、实盘人工确认，并明确不设账户回撤和单股仓位上限；以显式关闭标志记录，不再作为缺参阻断，也未强加单笔/单日金额阈值。若实际预算改变，须先通过对应金额的可执行性复验。数据、交易合法性和账本检查仍须通过。

下列情况至少停止受影响市场的新买入并阻断相关有效发布：行情过期/缺失、现金持仓无法对账、坐标修订未处理、证券交易状态无法核实、非法数量、重复结算、超预算或已批准风险阈值触发。是否撤单/卖出须按预先批准流程和真实可成交条件处理，不默认强制清仓，也不承诺止损价必能成交。其他市场只有在确认账户与故障隔离后才可继续。

## 5. 顺序、时间边界与审批范围

计划次序：P0 → P1 → P2 → P3 → P4。优先交付三个现任的可用性结论，再扩展候选。若数据缺口或运行耗时妨碍下周前完成，缩减挑战者数量，不省略账本、行情和执行硬检查；不承诺必能在目标日期上线。

审核本方案后，可开始本地证据整理、冻结输入、标准回放、必要验证工具与有限状态实现及隔离演练。生产部署、正式账户状态迁移、策略切换和实盘下单仍以具体结果及上线包为依据，不能把批准研究计划解释为上述动作均获授权。需要付费云运行时，先给出可审核的具体批次、预算和耗时。

最终交付：每市场一行的“保留 / 建议替换 / 仅参考 / 阻断”决策表，完整可复现证据索引，纠错影响解释，剩余缺口与有限上线限制，以及待批准部署包。记录所有失败尝试，不覆盖旧排行榜，不把过去已消费样本重新标成独立 OOS。
