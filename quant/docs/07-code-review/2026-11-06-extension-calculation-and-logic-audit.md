## 2. 已复现的问题

### Q01 / P1：基准缺失会删除策略净值，隐藏真实回撤

**位置**：`quant/code/execution/portfolio_performance.py:86–104`。

`return/cost/bench` 联合 `dropna()` 后，`account` 也只取剩余日期。输入策略账户 `100 → 50 → 100`，中间日仅基准收益缺失，函数输出最大回撤 **0%**，正确值是 **-50%**；同时输出 Sharpe **10.908712**，以及 `account_return_max_error=1`，但仍正常返回。

**影响**：基准缺口改变策略本身的风险和样本数；账户累计收益与日收益统计可能描述不同路径。调用方若只看 Sharpe/CAGR 可能错误选优。

**建议**：策略 account/return/cost 使用完整且唯一的交易日序列；基准缺失仅使相关指标不可用，或者明确拒绝整个报告，不能静默删日。校验所有有限数值；账户隐含日收益与 `return-cost` 超容差时不得继续输出可用于排名的指标。

**验收**：上述样例必须返回 -50% 策略回撤且标记基准不可用，或明确报错；补测首/中/尾日缺失、NaN/Inf、重复日和收益路径不一致。

### Q02 / P1：独立账本校验接受 NaN 汇总金额

**位置**：`quant/code/production/paper_accounting.py:79–131`。

把合法账本的 `cash`、`opening_cash`、`cost`、`portfolio_value_pre_trade_open`、`portfolio_value_close` 分别单独替换为 NaN，五个样例均 `verify_ledger(...) == True`。原因是 `abs(NaN) > tolerance` 为 False。

**影响边界**：正常 `execute_pending` 已有多处数值检查；这里复现的是独立审计/导入边界失效。`build_forward_performance` 额外检查 open/close NAV，但未对所有现金字段做同等有限数校验，不能据此认为全部 NaN 已被挡住。

**建议**：先集中校验所有原始字段、汇总字段、容差为有限数，并验证现金、费用与 NAV 的取值范围，然后做守恒计算；JSON 序列化用 `allow_nan=False`，解析端也拒绝 NaN/Infinity。

**验收**：逐字段 NaN、±Inf、负费用和非法现金注入均失败；合法零现金、正常分币误差通过。独立 verifier 不依赖调用方先清洗。

### Q03 / P1：前收盘价缺失时涨跌停限制失效

**位置**：`quant/code/execution/execution_limits.py:114–145,171–172`；生产调用 `modal_qlib_cn_a10g.py:1370–1439`。

普通主板股票，开盘 11、前收盘 NaN、收盘存在、factor=1，函数返回买卖均不阻止。`valid_prev=False` 被转换成“不限价”，没有表示“无法判断”。生产 context 对缺失前收盘也没有独立阻断。

**建议**：区分“已证明上市豁免/指数无涨跌停”和“缺少参考价”；普通股票缺前价应禁止相关成交或终止该日结算，记录原因。不要把数据坏点解释成可交易。

**验收**：普通股票前价 NaN/Inf/0/负数均不能成交；确有上市豁免且证据齐全的样本单独测试；同时验证缺 open/close 和数组长度不一致。

### Q04 / P1：浮点模拟 half-up 会算错一分钱限价

**位置**：`quant/code/execution/execution_limits.py:136–145`。

按代码自身的 10% 限价合同，前价 1.15 的跌停价为 `1.15 × 0.9 = 1.035 → 1.04`。当前二进制浮点 `floor(x*100+0.5)` 得到 1.03，开盘正好 1.04 时允许卖出，而正确掩码应阻止。

**建议**：参考价与 tick 计算采用经定义的 Decimal/整数刻度；同时明确 provider float32 重建价格误差如何处理。不能只在比较结果处加 epsilon 修复上一步的错误舍入。优先使用可溯源的官方除权参考价与涨跌停价。

**验收**：1.15/1.04 反例、精确半分边界、上下限、不同 factor 和 float32 输入，与独立 Decimal oracle 对照。修复后量化历史受影响订单，再重算相关指标。

### Q05 / P1：科创板也统一按 100 股买入

**位置**：`quant/code/production/paper_portfolio.py:43,369–407`。

现金 20,000、单只科创板股票价格 150、factor=1，当前模拟会买入 **100 股**。科创板新买入最低申报数量为 200 股，超过最低数量可按 1 股递增；不能使用主板的统一 100 股整手模型。[上交所规则第 6.7 条](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)、[上交所投资者教育问答](https://edu.sse.com.cn/tib/qa/)。

**影响**：即便独立 STAR 池未启用，宽基股票池仍可能包含科创板股票。100 股误成交，以及把合法 201 股等数量向 100 股倍数截断，都可能改变资金占用和收益。当前抽查的 6 份本地执行报告未见该小额误成交，历史覆盖率未量化。

**建议**：扩展层建立按板块/日期/订单类型区分的最小数量、递增单位和零股清仓规则，在 paper 与 research exchange 适配层共用；正确转换物理股数与 adjusted share units，不修改上游 Qlib。

**验收**：STAR 预算不足 200 股不得买入；预算可买 201 股时符合 1 股递增规则；覆盖 factor≠1、卖出不足 200 股的剩余头寸、主板 100 股和历史适用日。

### Q06 / P1：净值拼接的 25% 阈值不能证明账户连续

**位置**：`quant/code/ops/merge_forward_performance.py:101–125`。

回填终值 900,000，假设实时账户被重置为 1,000,000，当前拼接接受它并输出 **+11.1111% 日收益**。检查只比较金额变动是否小于 25%，输入甚至不需要边界持仓、现金和账户身份。

**边界**：这是“无法区分真实盈利与重置”的门禁缺口，不是已证实生产账户发生重置。真正 11.11% 盈利当然不能仅凭涨幅拒绝。

**建议**：拼接绑定 market/profile/lineage、initial cash、回填末状态 hash 与实时首个 opening state；逐项对账现金和 adjusted holdings，要求交易日连续且明示注资事件。25% 只能是异常提示，不能是身份和守恒证明。

**验收**：0.9M→1M 重置、同量级跨市场账户、缺边界交易日均失败；合法隔夜价格变动且现金/持仓衔接时通过。

### Q07 / P1：净值拼接丢失 ST 降级披露

**位置**：`quant/code/ops/merge_forward_performance.py:81–90,117–139`；前端 `quant/website/app.js:264–314`。

给 live 输入 `ST_IGNORED_REFERENCE_ONLY`、`st_fallback_dates` 和逐点执行政策，拼接输出全部丢失，并统一标为 `CONTINUOUS_SIMULATED_ACCOUNT`。前端允许政策字段缺省，无法恢复这部分来源信息。

**建议**：合并结果保留逐点 `data_mode`、执行政策、fallback dates、来源与状态边界；回填无相同证据时显式使用研究回填类别，不能伪装成 verified。同步调整前端 schema 以支持分段证据，不要给回填补造 ST 标签。

**验收**：verified/reference/backfill 混合输入经过构建→拼接→浏览器三步后，日期与政策不丢失；降级日必须仍可识别，未知政策拒绝。

### Q08 / P1（研究）：趋势过滤丢弃均线预热历史

**位置**：`quant/code/research/regime_reselection/run_g1_overlays.py:93–108,295–298`。

调用方读取 `bench_start` 以来的数据，但函数先 `close.reindex(report.index)` 再 rolling，回测起点以前的数据被丢弃。400 天持续下跌的价格，仅评估最后 100 天，已有充分 MA250 历史，实际权重仍全部 **1.0**，按规则应为 **0.3**。

**影响**：每次换回测起点会人为增加均线预热，尤其误判熊市开头的防御效果。不能据此宣称趋势策略有效或无效。

**建议**：在完整因果价格序列计算滚动指标和信号，shift 到下一交易日后再截取评估窗口；缺真实历史时显式报告 warmup policy。

**验收**：相同日期、相同历史下，完整回测与中途截取的权重一致；测试有/无足够历史和开盘执行时间边界。

### Q09 / P1（研究）：回撤熔断进入空仓后无法恢复

**位置**：`quant/code/research/regime_reselection/run_g1_overlays.py:120–180`。

第一天 -20%，随后 60 天每天 +10%，输出权重 `[1,0,0,...,0]`。hard breach 后空仓 NAV 不再随市场反弹，回撤永远低于 hard threshold；代码首先强制 target=0，恢复分支不可达。同时以自身空仓 NAV 高于 MA20 作为恢复条件也会形成闭环。

**建议**：明确状态机 NORMAL/REDUCED/CASH/RECOVERY，恢复用独立 shadow NAV 或基准趋势，并冻结恢复条件和高水位重置政策；若设计就是永久停止，则应改名并移除“5 日恢复”的误导描述。

**验收**：持续下跌保持空仓；充分反弹且满足预定义恢复条件后可重入；无来回抖动、无当日收盘决定当日开盘的前视。

### Q10 / P1（研究）：跨市场组合按毛收益漂移权重

**位置**：`quant/code/research/regime_reselection/run_g1_overlays.py:199–247`。

初始两袖各 50M，首日 A 毛收益 0、成本 10%，B 为 0；实际资产是 45M/50M。次日 A +10%、B 不变，正确终值 **99.5M**，函数输出 **99.75M**。它用 `w*(1+r)/(1+gross)` 更新权重，忽略了两袖费用差异。10% 是为了显式放大数学反例，不是实际费率假设；正常费率下同类偏差仍存在。

**建议**：从各袖实际扣费后资产更新权重；外层调仓费也要定义从哪个现金/资产账户扣除。输入报告先逐一校验日期完全相同，不能靠 DataFrame 自动对齐后比较共同 index。

**验收**：手算反例精确一致；费用相同/不同、有外层再平衡费、某袖日期缺失均覆盖；总资产等于各袖净资产加现金。

### Q11 / P1（研究）：成本压力后的 Sharpe 与净值不是同一收益序列

**位置**：`quant/code/research/csi300_csi500/stage0_p0_core.py:420–455`；`portfolio_performance.py:99–104,121–137`；G1 baseline 使用压力 Sharpe 于 `run_g1_baseline.py:201–203`。

冻结原账户 `[100,110]`，首日额外扣 1 元，压力账户 `[99,109]`。压力第二日日收益应为 `109/99-1=10.1010101%`，但 `return-cost` 仍是 **10%**。因此 CAGR/MDD 来自压力账户，而 Sharpe/波动来自另一条收益序列。

**建议**：可保留明确披露的“冻结成交名义金额、现金扣减”压力模型，但应从压力 NAV 及期初现金重新计算完整净收益，并一致更新 report 字段；或由指标层统一使用经过验证的 NAV 隐含收益。不要误把本问题理解为必须改成另一种压力模型。

**验收**：上述反例的第二日净收益等于 109/99−1；压力指标 `account_return_max_error` 接近零；零压力完全复原；1M/100M 首日基数正确；重新计算受影响的成本压力 Sharpe 和相关筛选门。

## 3. 静态确认的问题

### Q12 / P2：切池等待期间，旧请求仍可绘制旧市场内容

**位置**：`quant/website/app.js:990–1072,1085–1137`。

`switchPool()` 立即改变 currentPool 和页面标题，随后 await 新池 index；直到新池调用 `renderDate()` 才递增 `latestDateRequest`。在等待期间旧池 `renderDate()` 的 promise 完成，request 仍相等，`paint()` 可以写入旧池表格。若新池没有可用 index，旧请求甚至可能在“暂无信号”后再次回写。

已有 `loadForwardFor` 的 pool/request 双检查和 `switchPool` 的 index 返回检查，不能覆盖旧表格请求。此项是静态控制流确认，本次未运行真实浏览器延迟注入。

**建议/验收**：切池开始即递增 generation，所有异步 DOM 写入检查 generation+pool；清理旧数据/显示 loading。测试 A 慢请求→切 B→B index 延迟/空列表→A 返回，以及快速 A→B→A，标题、表格、净值与校验状态必须始终属于同一请求。

## 4. 设计缺口与待量化风险

### Q13 / P1：历史 ST 规则输入不是按日期的证券状态

`board_execution.py:51–58,88,117–150` 接受全窗口静态 `st_symbols`；G1/G2 baseline `run_g1_baseline.py:132` 不传历史 ST，等同默认空集合。虽然阈值函数支持日期，无法解决证券何时变为/退出 ST 的历史身份问题。

这是静态可确认的输入合同缺口；本次没有历史 ST 数据，不能断言影响多少股票和收益。建议按 `(instrument,date)` 注入可审计状态；无历史证据的实验标明 reference assumptions。验收用同一股票普通→ST→恢复三阶段，不得给全区间套今天名单或空名单。重新评估历史可成交性，而不是只改报告措辞。

### Q14 / P1：持仓使用调整后单位，缺少跨 provider 修订的坐标一致性证明

`PaperPortfolio` 持久化 adjusted shares/price；每日下载新数据，训练前缀修订会使模型重训，但这不自动证明旧持仓数量与新报价仍在同一复权坐标系。生产执行 context 读取新 factor，不见持仓坐标版本迁移的显式合同。

此项是风险，未证明当前数据包发生相关修订或现有 NAV 错误。建议冻结持仓坐标/来源快照，保留物理持股及公司行动账；出现纯归一化调整时必须证明 NAV 不变。验证现金分红、送转、除权及整段历史重标度，避免既改变股份又在总回报价格中重复计入收益。

### Q15 / P1（研究解释）：候选选择的不确定性不能由多个 phase 消除

已有大量模型、TopK/DropN、标签、phase、overlay 的历史试验。多个训练相位共享市场日期，不是相互独立的样本。旧终局报告已明确这一点，应继续落实到当前候选筛选和网站措辞。

建议建立完整试验登记（包括失败候选）、严格冻结搜索与评估窗口，使用嵌套 walk-forward、purge/embargo、时间区块 bootstrap、多重比较校正；PBO/Deflated Sharpe 可作辅助诊断，不能替代新前向数据。[回测过拟合原始研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。当前 2025–2026 扩展观察不得重新包装为未消费的独立验证。

验收应是模型/规则事前锁定、足够前向样本、成本压力及风险门均满足，而不是在相同历史上继续尝试直至出现更好收益。

### Q16 / P1（执行外推）：算术 overlay 和日线开盘成交不等于可执行账本

`run_g1_overlays.py` 直接缩放日收益并添加比例费用，`paper_accounting.py` 明示不建模盘口/部分成交。前者无法验证卖不出时能否按目标降仓；日收益缩放也无法准确区分前一夜持仓收益与当日开盘调仓后的收益。

建议把算术 overlay 定位为诊断筛选，晋级候选需转换为真实逐笔订单并重放现金/数量/限价/整手/最小费用。增加开盘可用流动性、成交参与率、部分成交和冲击成本的敏感性分析，按不同资金规模输出容量边界。本次未获得外部盘口数据，不声称已证明容量不足或具体收益折损。

## 5. 如果重新设计，我会如何改进

### 第一优先：统一资产与指标合同

建立单一成交/账户核心，研究和生产都调用同一输入输出合同；quote、factor、ST/IPO/停牌证据、订单、成交、现金、持仓和 NAV 都有日期、单位和版本。独立 verifier 保持另一套简洁的守恒推导，不能只是调用相同计算再比较。

先完成 Q01–Q07、Q11，并对已有真实账本执行缺价、非有限值、限价 tick、物理股数扫描。输出“影响日期/订单/市场/指标”，无法确认者保留待验证。历史修正另建版本，不覆盖不可变原始证据。

### 第二优先：修复研究工具，再讨论模型优劣

修复 Q08–Q11 后，用冻结预测重放受影响实验：不先换模型、不重新调参。比较纠错前后 CAGR、MDD、Sharpe、换手、成本压力与候选资格，若排序变化记录根因。修复缺陷本身不能作为自动切换生产策略的理由。

下一轮研究可预注册以下方向，收益改善需要新证据：

- 标签与执行一致：研究 T+1 开盘可获得的未来收益、超额收益或排序目标，并与现有 close-to-close 标签作固定实验比较。
- 组合管理：由 TopK 固定截断扩展到含行业/风格/个股权重约束、换手惩罚、流动性约束的组合；评估尾部损失和集中度，不只看平均收益。
- 风险层：先记录各池 beta、行业/市值/动量暴露及三池相关性，合并资金视角看重叠持仓；波动目标和回撤控制必须可交易回放。
- 评价层：净收益、最大回撤/恢复期、成本、最差时间段、参数稳定性和容量同时报告；避免把 raw 模型 score 当成概率或可直接投资的收益预测。

### 第三优先：将生产编排与研究隔离

`modal_qlib_cn_a10g.py` 当前 5,762 行，混有历史实验、数据构建、生产训练、状态管理和发布。建议渐进拆为 provider snapshot、training/inference、execution/account、publication、research adapters；生产入口只编排，不包含历史试验分支。

使用明确 schema 替代层层自由 dict，集中验证 market/profile/horizon/TopK/DropN/account/版本。引入交易日日历与可注入时钟；减少脚本间裸模块导入和 `sys.path` 差异。把数据清单、模型清单、订单/状态和 publication ID 串成可追溯链，保持现有 journal 恢复语义。

### 第四优先：测试覆盖业务不变量

现有测试可保留，新增测试应针对资产守恒、数据缺失、单位变换、日历连续和状态机可达性，而非复制实现公式。优先增加：

1. 固定种子属性测试：现金+持仓=NAV，无无来源股份，有限输入/输出，交易限制不因缺数据失效。
2. 独立 Decimal/tick、数量与费用 oracle；不同 factor 下同一物理订单等价。
3. 同一冻结信号与报价输入下，research/paper 的订单、成交和 NAV 逐日差分。
4. 故障注入：缺一个基准日、缺前价、账户回滚、跨市场错接、跨日期缺口、异步响应乱序。
5. 运维可观测性：发布失败原因、未结算订单年龄、数据/模型年龄、现金比例、异常持仓数量、连续零订单；不能仅监控任务返回成功。
