## 3. 部署与状态衔接的顺序

以下是具体包审核后的执行顺序；本轮尚未执行正式部署或正式状态写入。

1. **冻结部署输入。** 核对源码清单与待部署 checkout 一致；保留当前生产 app 版本、模型配置 SHA、三市场 profile/lineage、最新有效发布指针及各账户最后结算日。秘密和券商资料留在平台或受控运行记录中。
2. **备份当前状态。** 为三市场分别保存不可覆盖的现金/持仓/因子坐标、pending signal、结算历史、发布日志与模型身份副本，记录 SHA。备份失败则不迁移。
3. **隔离演练。** 将正式状态副本放入独立测试输出，验证迁移前后现金、股数和净值守恒；依次结算所有缺失交易日，不能直接跳到最新日。重复运行同一天须完全复现或拒绝冲突；在提交前中断后重试，不得重复扣费或更新有效发布指针。生产源卷先前发生的批量 I/O 故障尚未确认根因，不把训练成功当成正式状态卷恢复验证。
4. **区分账户类型。** 10/08 起新模拟账本只作为新版本候选；对旧模拟状态的替换需明确选定新 lineage 与切换边界，旧记录保留。实盘以券商实际现金、持仓和已成交委托为准；模拟单位是 Qlib 复权坐标，不能直接作为券商物理股数。空仓首建与已有持仓调仓分别计算。
5. **核对目标交易日。** 取得经核实的交易日历和上一个完整交易日行情、当日盘前 ST/停牌状态、执行价格参考和可用因子。任何覆盖缺口或坐标修订未处理，阻断对应市场有效订单。不能复用过期预测或将未知状态当作可交易。
6. **更新生产版本。** 仅在具体包获准且演练通过后，用授权本地 Modal profile 部署 `quant/code/production/modal_qlib_cn_a10g.py`。保留 app ID、源码清单、真实 CLI 退出码与部署后版本证据；部署成功后仍需完整日任务及失败恢复核验。
7. **人工逐单核对。** 比较信号日/执行日、市场/profile/账户身份、真实已有持仓、证券状态、买卖方向、股数、价格参考、费用和可用资金。每笔实际成交使用券商成交数量与价格登记；未成交和部分成交保留原状态，不能用模拟开盘成交覆盖。

正式运行前还缺目标日行情/状态、真实账户衔接和部署后的重复/中断恢复证据。`limited_rollout_readiness.py` 对每市场单独验收；`READY_FOR_LIMITED_REVIEW` 也只是可审核状态，不等于研究晋级或实盘授权。原 120 日研究晋级条件保持独立，不伪造日期来绕过。

## 4. 停止与恢复

数据失效、身份/坐标不一致、非法数量、现金透支、重复结算或账本不平时，停止受影响市场的新买入和有效发布，保留原始失败记录、pending 状态及最后有效指针。不同市场只有在账户与故障已确认隔离时才可继续。

恢复时先核对券商真实成交，再修复数据或状态，按原交易日顺序重放隔离副本并验收。代码回退不等于现金与持仓回退：不能覆盖故障期间新增的真实成交，也不能恢复已知错误代码后继续下单。没有可验证恢复路径时保留暂停执行状态，不默认强制清仓或假定停牌/跌停可卖出。
