# 每日选股：参数搜索对齐与每 20 交易日重训（待实测）

## 适用范围与状态

本改动仅适用于 `daily_standalone()` 的生产候选 `LightGBM + Alpha158 + 20 日标签 + csi1000 + top20/nd2`，**不自动改变**其他 Modal 研究任务、默认 YAML 超参数或股票池。`main` 尚未合并。单元测试/源码语法通过也不能代替真实 Modal 运行、实际交易和样本外检验。

## 超参数搜索：修复模型与评价口径错位

- `tune_one` 现在使用 `lgb158`，固定 20 日标签、`csi1000`、Top20、`n_drop=2`，与每日实际研究配置一致；其他预测周期必须另开显式研究任务，不能被混作生产超参。
- 使用已经 purge 的 **valid** 段生成预测，并仅在 valid 段运行 Qlib `TopkDropoutStrategy`，以扣除 `cost` 的基准超额收益均值年化作为搜索排序指标；Rank IC 仍记录作辅助诊断。模拟撮合默认按 `close`，买费 0.05%、卖费 0.15%，并非已经验证的真实次日开盘成交。
- 在随机参数前加入空字典 `{}`，表示 **完全不覆盖 YAML 原始参数的基线**。搜索输出包含模型、股票池、TopK、n_drop 和验证净收益；**不会自动把验证期表现第一的参数部署到每日程序**，需要独立外层样本外和前向检验。
- 当前 valid 区间既用于 LightGBM early stopping 又用于超参比较，依然存在多重选择偏差；本次仅修复“调别的模型、用 IC 代替组合结果”的明显错位，不能宣称最优参数。

## 每日评分、每 20 个交易日更新模型

1. 每天取得截至当日已经发布完毕的数据；当天仅用于 `test=[asof,asof]` 生成评分，**没有当天的未来 20 日标签**。
2. 初次运行或距离上次成功训练达到 `20` 个交易日时重新训练。以最新日期 `T` 为预测日，从 `T` 向前留出 20 日标签到期缓冲，之前选取最近 252 个交易日做验证；训练从 2016 年开始 expanding，并在 train/valid 边界再 purge 20 日标签。模型、预处理拟合边界与日期记录在 Volume。
3. 其他交易日从 `/vol/live_models/` 读取已训练模型，在当日新数据上创建 inference dataset；**保持缓存模型原来的训练、验证区间和处理器拟合区间**，绝不使用新一天的数据重新拟合预处理器。
4. 缓存按模型配置、handler/因子、标签、股票池、训练策略版本生成签名，记录训练日期与模型 SHA-256；模型与元数据不成对或完整性错误时终止。参数变更后自动使用不同签名，触发新训练。
5. 重训成功时先临时写入模型和 JSON，再原子替换并 `vol.commit()`。注意：同一签名的并发写入和数据供应方追溯修订仍需单独运维限制/版本审计；不要同时运行多个同配置 daily 实例。只从可信 Volume 读取 Python pickle。
6. 函数返回 `model_fit_asof`、`train_end`、`valid_end`、`retrained_today` 供审计，CSV 仍为排名，**不是可执行交易单**；实际持仓、成交失败与次日订单处理不在本 PR 范围内。

## 验收与建议的频率对照

- 交易日历、成熟标签边界、缓存重训间隔和模型参数缓存失效必须通过单元测试。
- 真正部署前需跑 `modal run modal_qlib_cn_a10g.py --best --daily` 的新模型训练日与下一非训练日，确认缓存复用、特征尺度一致、模型 pickle 及数据卷正常，再跑历史逐日模拟。
- 预先固定同一套候选（例如每 5／20／60 个交易日重训一次），只用各时间点已可用的数据做外层 walk-forward，在完全相同的交易成本和持仓规则下比较**扣费净超额、回撤、换手、持仓天数和稳定性**。20 个交易日只是工程基线，并非经过验证的最优频率。
- 2026-09-18 旧实验的收益数字未经本次新调度、标签边界和缓存方案完整重跑，不得直接沿用。
