# 风险条款、代码审计与资源规范

## 已知风险与局限（资金安全相关）

1. **信号期望极薄**【滚动实证】：21 个月滚动年化超额 +0.47%（窗口数字 +9.4% 不可作为预期）。季度波动 ±20%，最差单季 -19.6%。
2. **成本决定生死**【推算实证】：真实费率万一约 +2.2%、悲观双倍 -2.4%——先确认自己的实际成交条件再谈策略。
3. **月度极不稳定**：11/21 个月正超额；连续 3 个月为负属正常剧本。
4. **风格切换失效**：2026Q2 单季 -19.6% 表明信号在市场风格切换期完全失效——大盘门控/减仓规则是必要保险。
5. **复权因子前视**【已实证排除】：chenditc append-only（两包 6154 只股票零差异），restatement bias 不存在；残余注意：训练用历史数据 vs 实盘实时数据的口径差异，以 paper trading 为最终校验。
6. **回测成交价 vs 实际执行**：回测按当日收盘成交，实盘次日开盘执行——隔夜跳空为噪音型偏差（预期 <<1%），已评估不构成决策因素。
7. **涨跌停过滤口径**：当日涨幅 = close/前收 − 1，|涨幅|≥9.5% 剔除（创业板/科创板 20% 涨跌幅股会被提前剔除——保守方向可接受）。
8. **模型只提供排序**：不提供仓位、止损、择时——风控规则见 playbook。

## 代码审计记录（2026-09-16/17）

发现并修复 3 个**静默失效型** bug（不崩溃、给错结果——最伤钱的类型），全部位于信号输出路径，不影响研究路径：

| Bug | 影响 | 修复与验证 |
|---|---|---|
| 涨跌停过滤公式错（close/open 日内振幅≠涨幅） | 误剔除非涨停高振幅股 | 改为 close/前收；与 $change 口径逐日计数 100% 一致 |
| 涨跌停过滤 index 对齐错 | **过滤从未生效**（isin 双层 vs 单层永 False） | 取 instrument 层后 isin；实证 09-16 正确剔除 7 只 |
| --daily 不带 --long-train | 实盘信号用了短训练模型 | 运行时警告 + 固化入口 --best --daily |

**影响面结论**：所有训练/回测/IC/参数选择走 QLib 引擎路径且日志留有 long_train=True 证据——研究结论全部有效；仅 2 份实盘榜单作废并重生成。

**审计工具**：`modal run modal_qlib_cn_a10g.py::verify_integrity`——验证 $change 语义、过滤口径、每日涨停数。**建议每次实盘建仓前跑一次**。

## Modal 资源使用规范

- Starter 计划：并发容器 100、GPU 并发 10、月免费 $30
- **GPU 只挂给 RNN 系模型**；LGB/数据/搜索全走 CPU（挂载未使用=按挂载计费，浪费）
- 超参类并行任务：8 并发 × 16 核以内
- **不要 --detach**（本地断开后约 10 分钟输入被平台取消，已两次实证）；长任务用普通 modal run 保持本地连接
- `.map()` 不接受并发参数——并发控制在 `@app.function(max_containers=N)`
- 结果持久化到 Volume 后**必须 vol.commit()**，再 `modal volume get` 取回本地入库
- **架构（2026-09-19 审计 PR 合并后修订）**：`--best --daily` 单容器运行（无 GPU），数据仍每次全量下载（必然最新），
  但**重新依赖 Volume**：`/vol/live_models` 模型缓存（每 20 个交易日重训一次，其余日复用缓存模型，SHA-256 校验）；
  换 workspace 需 `modal token new` + 重建 Volume（首次运行自动重训）
- Volume `qlib-cn-data` 现承载两职：① 研究批（--batcha/b/c、--p2 等并行 map）共享数据；② daily 模型缓存
